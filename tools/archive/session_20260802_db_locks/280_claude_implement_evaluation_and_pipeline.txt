【ミッション: SFT->DPO直列パイプラインの開通と自動評価ゲート（実推論）の統合】
データフライホイールを完成させるため、オーケストレーターの配線と評価スクリプトのモック解消（実推論の実装）を行います。

Step 1: オーケストレーターの直列配線 (tools/mlops_pipeline_nazo.py)
mlops_pipeline_nazo.py を改修し、学習ステップにおいて以下の順にサブプロセスを直列実行するようにASTを書き換えてください。

["uv", "run", "python", "tools/train_nazo_sft_model.py"] (事前学習: SFT)

["uv", "run", "python", "tools/train_nazo_model.py"] (選好最適化: DPO)
※親プロセスがVRAM_LOCK_HELD_BY_PARENT_ENVを設定してロックを保持しているため、直列実行すればOOMは発生しません。

Step 2: 自動評価ゲートのモック解消 (tools/evaluate_model.py)
現在ダミーのスコアを返している evaluate_model.py を実推論ロジックに置き換えてください。

VRAM 8GB防弾仕様（load_in_4bit=True等）と遅延インポート（# pyright: ignore）を適用し、unslothの FastLanguageModel を用いてベースモデル(elyza:8b)とDPO学習済みLoRA(models/nazo_lora)をロードすること。

テストデータ（data/sft_dataset.jsonl等）から数件（例: 5〜10件）をサンプルし、推論（generate）を実行してください。

評価メトリクス: 生成されたテキストがなぞかけの基本フォーマット（「とかけて」「ととく」「その心は」等のキーワードが含まれているか）を満たしている割合（フォーマット遵守率: Format Adherence Rate）をスコアとして算出してください。

算出スコアとベースライン（run/audit_reports/baseline_metrics_nazo.json）を比較し、退行していなければパス（Exit 0）、退行していればフェイル（Exit 1）とするゲートキーパーロジックを実装してください。

最後に確実にVRAMを解放（gc.collect, torch.cuda.empty_cache等）すること。

Step 3: 静的解析とコミット
uv run ruff check tools/ による静的解析を通過させた後、変更したファイルを明示的に指定してGitコミットを行ってください。
※絶対制約: git add . は厳禁です。
