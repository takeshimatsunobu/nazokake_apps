【ミッション: Cloud Runマルチインスタンス下における状態同期（Pull）の修復】
生成ステータスポーリング時に404エラーが発生する問題（ローカルSQLiteのインスタンス間不整合、および外部ワーカー進捗の未反映）を根治するため、以下の要件に従いコードを修正してください。

Step 1: 該当ロジックのAST解析
apps/evaluator/backend/api/routers/generate.py の get_status エンドポイント、およびデータベースの取得ロジック（async_get_item 等）を走査してください。

Step 2: Firestoreフォールバックと能動的Pullの実装
get_status において、以下のロジックを実装してください。

async_get_item(doc_id) が None を返した場合（別インスタンスへのルーティング時）、即座に 404 を返すのではなく、Firestoreから直接当該 doc_id のドキュメントを取得する。存在した場合はSQLiteへ保存（同期）して処理を継続する。存在しない場合のみ 404 を返す。

ローカルSQLiteにデータが存在しても、ELYZAワーカーの処理待ち（elyza_job_status が pending や processing 等）である場合、Firestoreから最新のドキュメントをPullし、ワーカーが直接Firestoreに書き込んだ最新の進捗（completed 等）でローカルSQLiteを上書き同期してからレスポンスを返す。
※文字列置換は使用せず、ASTを介した安全な操作または手動での正確な修正を行うこと。

Step 3: 静的解析と厳密なコミット
実装後、RuffとPyrightを用いて構文・型エラーがないことを確認してください。
検証完了後、変更したファイル群を明示的に指定してGitコミットし、リモートの main ブランチ（または作業ブランチ）へ push してください。
※絶対制約: git add . は厳禁です。必ず対象ファイルパスを個別に指定すること。
