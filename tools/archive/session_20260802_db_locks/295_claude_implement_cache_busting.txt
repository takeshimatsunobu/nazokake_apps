【ミッション: フロントエンドのキャッシュ・バスティング（Cache Busting）の実装】
Firebase Hostingにおける旧バージョンのJSファイルのキャッシュ残存（アセット・スキュー）が原因で、不整合なFetchやUIエラーが発生している。これを防ぐため、index.html の Import Map にキャッシュバスティングを実装せよ。

Step 1: バージョンスタンプの生成ロジック追加
フロントエンドのビルド/デプロイフローが存在しない素のJS配信であるため、index.html への静的なクエリパラメータ付与（例: ?v=1.0.1）を行う。
apps/evaluator/frontend/public/index.html を解析し、<script type="importmap"> 内のすべてのローカルJSファイル（/config.js, /api.js, /ui/result.js 等）のパスの末尾に、現在のUnixタイムスタンプまたは任意のバージョン文字列（例: ?v=20260802）をクエリパラメータとして付与せよ。
これにより、ブラウザに強制的に最新のJSファイルをフェッチさせること。

Step 2: Service Workerのキャッシュパージ
apps/evaluator/frontend/public/sw.js の install または activate イベント内に、旧バージョンのキャッシュが存在した場合にそれを強制的に削除（パージ）するロジック（もし既存のキャッシュAPIを使用している場合。使用していなければスキップでよい）を追加、あるいはService Worker自体の更新をブラウザに強制するコメントの変更（バイト列の変更）を行え。

Step 3: 静的解析と厳密なコミット
実装後、HTMLの構文エラーがないことを確認せよ。
検証完了後、変更したファイル群を明示的に指定してGitコミットを行え。
※絶対制約: git add . は厳禁である。必ず対象ファイルパスを個別に指定すること。
