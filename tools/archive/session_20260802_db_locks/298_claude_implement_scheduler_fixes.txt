【ミッション: MLOpsスケジューラーのOS境界修復とコンテナ防弾化の実装】
SREの絶対原則に基づき、Linuxコンテナ内でスケジューラーが確実に稼働・自律復旧できるよう、以下の3点の要件（Must Fix）を満たすようにコードおよびインフラ定義を静的に修正してください。

Step 1: OS依存起動の排除と決定論的パス解決 (tools/mlops_trigger.py)
tools/mlops_trigger.py をASTベースのツール（LibCST等）または安全なエディタ操作で静的に書き換えてください。

sys.platform を用いた条件分岐を追加し、Windowsの場合は従来のPowerShell経由、Linux (sys.platform == "linux") の場合は PowerShell を介さない直接起動へと分岐させてください。

Linuxでの起動時は shutil.which("uv") を用いて uv コマンドの絶対パスを決定論的に解決し、サブプロセス（uv run python tools/mlops_pipeline_nazo.py 等）を安全に実行するように実装してください。動的なモンキーパッチは厳禁です。ソースコードを静的に書き換えてください。

Step 2: Graceful Shutdown（安全な終了処理）の実装
tools/mlops_trigger.py または関連するエントリポイントにおいて、signal モジュールを用いて SIGTERM および SIGINT を捕捉（トラップ）するロジックを追加してください。
OSまたはDockerデーモンから停止シグナルを受けた際、実行中の中途半端な状態を安全にクリーンアップし、冪等性を損なわない形でプロセスを終了（Graceful Shutdown）するようにしてください。

Step 3: コンテナの防弾化とヘルスチェック (docker-compose.yml)
infra/docker-compose.yml (または該当する本番/検証環境のComposeファイル) を修正してください。

mlops-scheduler および data-sync-daemon サービスに restart: unless-stopped を明示的に追加してください。

各サービスに対して、プロセスのハングアップを検知するための healthcheck ディレクティブ（定期的にプロセス生存またはポート応答を確認する設定）を追加し、自律的な再起動をOSレベルで保証してください。

Step 4: 静的解析と厳密なコミット
実装後、Ruff等でPythonコードの構文エラーがないこと、および docker-compose config でYAMLの構文が正しいことを確認してください。
確認完了後、変更したファイル群を明示的に指定してGitコミットを行ってください。
