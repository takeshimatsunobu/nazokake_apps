【ミッション: シークレット管理のSSoT（Single Source of Truth）化とリファクタリング】
現在、GEMINI_API_KEY などの環境変数の読み込みロジックがプロジェクト内に散在している疑いがある。アーキテクチャのDRY原則に従い、キーの取得経路を1箇所に統合せよ。

Step 1: コードベースの全検索
プロジェクト全体から GEMINI_API_KEY という文字列を含むコードを検索せよ。
※絶対制約: もし実際のキー（AIza...等）がハードコードされているのを発見した場合、その値自体は絶対にターミナル出力やコミットメッセージに含めないこと（マスキングすること）。

Step 2: SSoTモジュールの確立
packages/shared_core/src/nazokake_core/ などの共有コア領域（存在しない場合は最適な共通領域）に、環境変数を一元管理する env_config.py（または既存の config.py の拡張）を作成/更新せよ。
dotenv（python-dotenv）等を用いてルートの .env を確実に読み込み、そこから GEMINI_API_KEY を取得して提供する唯一の窓口（プロパティや関数）を定義せよ。

Step 3: 依存コードのリファクタリング
Step 1で発見した、各ファイル（evaluation.py 等）での直接的な os.environ.get("GEMINI_API_KEY") や os.getenv の呼び出しを、すべて Step 2 で作成した SSoT モジュールからの import に置換せよ。

Step 4: 静的検査とコミット
RuffやPyright等のローカル静的検査を通過することを確認後、変更したファイル群をコミットし、現在の作業ブランチ（または新規ブランチ）に Push せよ。
※絶対制約: git add . は厳禁である。変更したファイルのみを個別にステージすること。
