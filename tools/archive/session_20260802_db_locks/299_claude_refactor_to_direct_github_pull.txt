【ミッション: VM内Bareリポジトリの廃止と、GitHub直結の真のPull型デプロイへの移行】
IAPトンネルを経由した大容量の git push が帯域制約により Broken pipe を引き起こしている。VM内の中継地点（Bareリポジトリ）を廃止し、VM自身が直接GitHubからコードを同期する完全なPull型アーキテクチャへデプロイスクリプト群をリファクタリングせよ。

Step 1: tools/deploy/deploy_to_vm.ps1 の改修

ローカルからVMのBareリポジトリへ git push を行うステップ（[4/5] Pushing branch... 等）および、それに関連するBareリポジトリの存在チェック処理を完全に削除せよ。

スクリプトの役割を「VMの起動・SSH開通確認」と「VM上で直接 infra/verification_env/deploy_pull.sh を非同期キックするコマンドの送信」のみに純化させよ。

Step 2: infra/verification_env/deploy_pull.sh の改修

BARE_REPO_DIR への依存と、そこを対象とした git fetch 処理を完全に削除せよ。

稼働ディレクトリ（~/nazokake_apps）において、リモートURLが確実にGitHub（https://github.com/takeshimatsunobu/nazokake_apps.git）を向いていることを担保した上で、直接 git fetch origin および git reset --hard origin/main を実行する決定論的同期へ変更せよ。

指示書200で実装した auto_shutdown.py の同期（install -m 755）や、その他のフェイルセーフ機構は一切損なわずに維持すること。

Step 3: 静的解析と厳密なコミット
実装後、AST解析やRuff、PowerShellの構文チェックを用いてエラーがないことを確認せよ。
確認完了後、変更したファイル群を明示的に指定してGitコミットを行え。
※絶対制約: git add . は作業ツリー汚染の温床となるため厳禁である。必ず対象ファイルパスを個別に指定すること。
