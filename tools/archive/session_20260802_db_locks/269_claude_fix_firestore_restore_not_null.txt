【ミッション: Firestoreリストア時のスキーマ後方互換性の確保】
起動時の firestore_restore 処理において、Firestore上の古いデータに新設カラムが存在しないために発生する SQLite の NOT NULL constraint failed: nazokake_items.elyza_job_retry_count エラーを修正し、リストアを完遂させてください。

Step 1: リストアおよびパースロジックの特定
firestore_restore を実行しているモジュール（packages/shared_core/nazokake_core/ の firestore_sync.py や database.py、または schemas.py）をASTで走査し、Firestoreの辞書データを SQLite (ORM) または Pydantic モデルへマッピングしている箇所を抽出してください。

Step 2: デフォルト値補完（後方互換性）の実装
古いFirestoreドキュメントをパースする際、elyza_job_retry_count が存在しない（または None / null）場合は、デフォルト値として 0 を補完する安全なパースロジックを実装してください。Pydantic モデル（NazokakeItem 等）側で Field(default=0) を設定する、あるいはリストア関数内で辞書をサニタイズする等、最も堅牢な手法を採用すること。
※ elyza_job_status や elyza_job_locked_at などの新設フィールドも、過去データには存在しないため、同様にSQLiteのスキーマ定義（Nullable許容など）と矛盾しないよう補完処理を入れること。

Step 3: 厳格なコミット
実装後、Ruff等で構文エラーがないことを確認してください。
確認完了後、変更したファイル群を明示的に指定してGitコミットを行ってください。
