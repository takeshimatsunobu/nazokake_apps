【ミッション: GitHub Actionsによる完全なGitOps (CI/CD) パイプラインの構築】

ローカルや特定のVM（Bareリポジトリ）に依存するデプロイ運用を廃止し、完全なGitOpsアーキテクチャを確立します。以下の要件（Must Fix）に基づき、GitHub Actionsのワークフローを実装・改修してください。

Step 1: CI (Continuous Integration) ゲートキーパーの実装
.github/workflows/ci_pr_check.yml（既存の場合は改修、なければ新規作成）を以下の要件で実装してください。

トリガー: main ブランチ宛の pull_request イベント。

環境構築: ubuntu-latest 上で、uv を用いて高速かつ決定論的にPython環境と依存関係をセットアップする。

テスト実行: pytest を実行し、既存のテストスイートをパスすることを確認する。

静的型検査: python tools/pyright_tool.py --gate を実行し、ラチェット方式の型検査を通過することを確認する。
※ いずれかのステップが失敗した場合は Exit 1 となり、PRのマージを確実にブロック（Fail-Closed）する設計とすること。

Step 2: CD (Continuous Deployment) 自動化の実装
.github/workflows/cd_main_deploy.yml（既存の deploy_cloud_run.yml 等がある場合はそれを改修）を以下の要件で実装してください。

トリガー: main ブランチへの push イベント（PRマージ時に発火）。

GCP認証: GitHub Secrets (WIF_PROVIDER, WIF_SERVICE_ACCOUNT) を使用した Workload Identity Federation によるパスワードレス認証を行う。

ビルド＆デプロイ: gcloud builds submit または Artifact Registry への Docker イメージ Push を経て、Cloud Run へ最新リビジョンをデプロイする。

ログ出力: デプロイ完了後、成功/失敗のステータスがGitHub Actionsのログとして明確に残るようにする。

Step 3: 安全性の担保とAST検証
実装した YAML ファイルがGitHub Actionsの構文として正しいか検証してください（Actionlint等のツール、または厳密な目視確認）。
実装完了後、この変更自体を「PRベースのワークフロー」を用いてリモートへ提出（Commit, Push, PR作成）してください。ローカルの main へ直接コミットしてはなりません。
