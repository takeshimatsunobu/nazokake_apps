【SREアーキテクト監査：構成ドリフトの解消とFail-Closed原則の徹底】
前回の実行ログにおいて、Git不在によるクリーンアップ失敗（[Errno 2] No such file or directory: 'git'）を例外処理で握り潰し、処理を続行（Fail-Open）する挙動が確認されました。SREの観点から、このサイレント障害を放置したアーキテクチャは直ちに Reject（差し戻し）とします。
以下の是正要件（Must Fix）に基づき、IaCとアプリケーションコードを修正してください。

Dockerfileへの Git 注入（構成ドリフトの解消）
infra/verification_env/mlops_scheduler.Dockerfile の依存関係インストール層（apt-get等の実行部分）に git パッケージのインストールを明示的に追加し、コンテナ内に必ずGitコマンドが存在する状態をIaCとして保証してください。

クリーンアップ処理の厳格な Fail-Closed 化
tools/mlops_trigger.py または関連するクリーンアップ呼び出し箇所において、FileNotFoundError 等のインフラエラーが発生した場合、例外を捕捉してログ出力や pass で済ませる設計を撤去してください。エラー時は直ちに Exit 1 を送出し、フライホイールの処理を完全に遮断（Fail-Closed）するようロジックを修正してください。

実装後、静的解析を実行し、変更したファイル群を明示的に指定してGitコミットを行ってください。
※絶対制約: git add . は厳禁です。必ず対象ファイルパスを個別に指定すること。
