【ミッション: エフェメラルVMアーキテクチャのSPOF排除（デッドマンズスイッチと排他制御の実装）】
ローカルスクリプトの異常終了に伴うGCP VMの放置（クラウド破産リスク）および多重トリガー発火による競合を防ぐため、クラウドネイティブなフェイルセーフと排他制御を実装してください。

Step 1: クラウドネイティブなデッドマンズスイッチ（TTL）の導入
tools/deploy/run_ephemeral_pipeline.ps1 （または対象のプロビジョニングスクリプト）内の gcloud compute instances start コマンドを改修してください。
・--metadata オプションを利用し、startup-script として sudo shutdown -h +180 （起動から3時間後に強制シャットダウン）等の時限停止コマンドをGCP VMへ注入すること。
・これにより、ローカルスクリプトの finally ブロックが発火しないハードクラッシュ時においても、VMが自律的に停止するクラウド側のフェイルセーフを確立してください。

Step 2: トリガー実行時の決定論的排他制御
tools/mlops_trigger.py を改修し、多重プロビジョニングを防ぐロック機構を実装してください。
・filelock ライブラリを利用し、run/.vm_provision.lock などの一意なロックファイルを取得する設計に変更すること（timeout=0）。
・すでにロックが取得されている場合は例外をキャッチし、競合とみなして何もしないまま安全にプロセスを終了（Exit 0）させること。

Step 3: 静的解析と厳密なコミット
実装後、uv run ruff check tools/ およびPowerShellの構文チェックを行い、エラーがないことを確認すること。
検証完了後、変更したファイル群を明示的に指定してGitコミットを行ってください。
コミットメッセージ例: "feat(infra): GCP VMのデッドマンズスイッチ(TTL)とトリガー排他制御の実装"
※絶対制約: git add . は厳禁です。必ず対象ファイルパスを個別に指定すること。
