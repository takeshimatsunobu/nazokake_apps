【ミッション: Gitマージステートに基づくエスカレーションリソースの自動クリーンアップ機構実装】
Nazo-Agentの自律稼働に伴って蓄積される一時Git Worktreeおよびブランチについて、ストレージ枯渇を防ぐためのガベージコレクションを実装してください。経過時間による推測削除はシステム破壊の温床となるため禁止し、必ず「マージ状態」を絶対基準としてください。

Step 1: クリーンアップスクリプトの作成
tools/cleanup_git_resources.py を新設し、以下のロジックを実装すること。
・ロギングの徹底: 削除対象の判定理由、削除されたWorktreeパス、ブランチ名を標準出力または既存のロガーで記録すること（可観測性の確保）。
・マージ判定の堅牢化: git branch --merged main に加え、Squash Merge等でコミットハッシュが変わった場合を考慮し、リモートの追跡ブランチとの差分がない、あるいは明確に不要と判定できるロジック（※実装方法はAgentに提案させるが、安全側に倒すこと）を含めるか、厳密にFast-forward/Merge commitされたもののみを対象とする仕様を明記する。
・安全な削除: 抽出されたマージ済みブランチに関連する worktree パスを取得し git worktree remove --force を実行。その後 git branch -d でブランチを削除。未マージは一切操作しない。
・Dry-run機能: 環境変数 DRY_RUN=true の場合は実際の削除を行わず、削除予定のリストをログ出力するだけに留めること。

Step 2: スケジューラーへの自動化統合
作成したクリーンアップ関数を tools/mlops_trigger.py のメインループ末尾（または既存のクリーンアップ処理のブロック内）に統合すること。
※統合時の注意: 既存の処理フローやコード行を一切削除・圧縮してはならない（情報欠損の厳禁）。文字列の単純置換ではなく、Pythonの標準 ast モジュールを利用した構文解析に基づく安全なコード挿入、またはそれに準ずる安全性が担保された編集手段を必ず用いること。

Step 3: 静的解析と厳密なコミット
実装完了後、uv run ruff check tools/ を実行し、構文エラーがないことを確認してください（--fixは使用しないこと）。
検証完了後、追加および変更したファイル群を明示的に指定してGitコミットを行ってください。
コミットメッセージ例: "feat(infra): Gitマージステートに基づく一時Worktreeの安全な自動クリーンアップ機構の追加"
※絶対制約: git add . は厳禁です。必ず対象ファイルパスを個別に指定すること。
