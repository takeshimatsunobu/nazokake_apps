【ミッション: 環境ガードとローテーション付きローカルDB初期化スクリプトの開発】
スキーマ変更時のブロッカーを解消するため、ローカルDB（SQLite）を安全にバックアップ・削除し、最新スキーマで再作成する運用ツールを構築してください。

Step 1: 初期化スクリプトの基本実装
tools/init_local_db.py を新規作成し、packages/shared_core/nazokake_core/database.py に定義された最新のスキーマ（NazokakeItemORM等）をインポートした上で、SQLAlchemyの Base.metadata.create_all() を呼び出して空のDBを生成する処理を実装してください。

Step 2: 【厳格な制約1】フェイルセーフ（環境ガード）
スクリプトの実行開始時に、コマンドラインプロンプト（例: "本当にローカルDBを初期化しますか？ [y/N]: "）を表示し、'y' または 'Y' 以外が入力された場合は直ちに sys.exit(1) で安全に終了するロジックを必ず組み込んでください。誤爆によるデータ全損を物理的に防ぎます。

Step 3: 【厳格な制約2】バックアップローテーション
既存の SQLiteファイル（例: nazokake_local.db）が存在する場合、削除する前に必ずタイムスタンプを付与した名前（例: nazokake_local_YYYYMMDD_HHMMSS.db.bak）でバックアップを作成・退避してください。
さらに、退避先のディレクトリ内でバックアップファイルが5世代（最新5個）を超えた場合、古いものから自動的に削除（クリーンアップ）するローテーション処理を実装してください。

Step 4: 静的解析と動作確認
修正後、uv run ruff check --fix tools/init_local_db.py を実行して構文をクリーンに保ってください。
その後、実際にスクリプトを実行し、以下の2点を確認するスモークテストを行って結果を報告してください。

プロンプトで 'N' を入力した際に安全に中断されること。

プロンプトで 'y' を入力した際にバックアップが作成（またはローテーション）され、新しいDBが生成されること。
最後にGitへのコミットを行う場合は、推測による git add . は厳禁です。必ず新規作成・変更したファイルのみを指定してコミットしてください。
