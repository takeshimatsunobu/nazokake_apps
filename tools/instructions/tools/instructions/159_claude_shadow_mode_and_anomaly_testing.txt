【ミッション: ゼロトラスト原則に基づくシャドウモード運用の強制と異常系ベンチマークの追加】
ファクト評価と次期フェーズへの移行判断について、SREの観点から明確に差し戻し（Reject）を通達します。
6次元ベンチマークのハッピーパス通過によるインフラの完成はApproveしますが、それを根拠に直ちに「メインリポジトリへの自動マージ（完全自律化）」へ移行する判断は、ゼロトラスト原則の違反およびSSoTの忘却です。
以下の要件（Must Fix）に基づき、完全自律化前の「シャドウモード運用」の設計案と実装を行ってください。

Step 1: 異常系ベンチマークの追加強制
Qwen単独では解決不可能な難易度のFixture（ダミー課題）を tools/benchmark/fixtures/ に追加してください。CTOモデルへのエスカレーションが確実に発火し、「時間対品質パリティ」の評価ロジックが機能することを動的に証明するテストシナリオを実装すること。

Step 2: Pull Request（PR）駆動への制約（シャドウモードの強制）
過去のSSoT（6. Autonomous Repair & Escalation Loop）に定義されている通り、修正適用時は必ず隔離ブランチを作成し、自動マージではなく「PRドラフトの生成」で処理を一時停止（Suspend）するフローを厳格に実装・維持していることをコードレベルで証明すること。メインブランチへのWrite権限行使は許可しない。

Step 3: 経験再生アーキテクチャのループ完結の証明
ベンチマークを通過したという「成功体験」が、確実に ai_knowledge_base.json へフィードバック（記憶の更新）されていることを客観的に証明するロジック、またはその稼働ログの出力を要件に含め、実装すること。

Step 4: 静的解析とコミット
実装後、uv run ruff check tools/ を実行して構文エラーがないことを確認してください（--fixは使用しないこと）。検証完了後、変更したファイル群を明示的に指定してGitコミットを行ってください。
※絶対制約: git add . は厳禁です。必ず対象ファイルパスを指定すること。
