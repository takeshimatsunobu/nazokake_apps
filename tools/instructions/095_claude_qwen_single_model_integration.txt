【ミッション: VRAM制約をクリアするQwen Coder単一モデル常駐化と防弾ループの実装】
RTX 4060（VRAM 8GB）の物理制約をクリアしつつI/O遅延（スラッシング）を防ぐため、tools/agent_graph.py のローカル修復ループを「qwen2.5-coder:7b 単一モデルによるマルチロール（プロンプト切り替え）稼働」へと再構築してください。

Step 1: 単一モデル（Qwen 7B）によるマルチロール・オーケストレーション
tools/agent_graph.py を開き、LangGraphの処理ノードを以下のように再構築してください。
・VRAMの物理制約（8GB）を回避するため、複数モデルの切り替え（アンロード/ロード）は絶対に禁止します。
・【現場監督ノード】および【職人ノード】の両方の推論に qwen2.5-coder:7b のみを使用してください。
・同じモデルに対し、「エラーログを解析するプロンプト」と「AST置換用JSONを出力するプロンプト」をLangGraphのノードごとに切り替えて渡し、役割（ロール）を演じ分けるシングルモデル・マルチロール体制を実装してください。

Step 2: 7Bモデル特有のJSON出力の脆さに対する防弾化（絶対制約）
小規模モデル（7B）はJSONフォーマットを崩すリスクが高いため、以下の2つの防弾機構を必ず組み込んでください。

【Few-shot注入】: 「職人」ノードのシステムプロンプト内に、期待する正しいJSON出力の例（対象ファイル、関数名、置換コードの3点セットのフォーマット例）をFew-shotとして明記してください。

【Pydantic検証と自己修正(Retry)ループ】: 職人ノードが出力した文字列をPydantic等でパース・検証し、JSONエラーやスキーマ違反が発生した場合は即座にクラッシュさせず、エラー内容（ValidationErrorの文字列）をプロンプトに含めて再度Qwenに修正を要求する「Retryループ（最大3回程度）」をLangGraphのステートマシン内に構築してください。

Step 3: 静的解析とスモークテスト
修正後、uv run ruff check --fix tools/agent_graph.py を実行して構文をクリーンに保ってください。
その後、ダミーのエラーログ等を用いて agent_graph.py のフローをドライラン（またはテスト実行）し、以下の2点を確認して報告してください。

qwen2.5-coder:7b モデルが単一で呼び出され、プロンプトの切り替えにより役割を演じ分けて推論が行われること。

意図的に壊れたJSONをモックで返却させるなどして、Retryループ（自己修復）が正しく発動し、最終的にエラーがハンドリングされる経路が機能すること。
確認後、変更した tools/agent_graph.py のみを明示的に指定してGitコミット（例: "feat(tools): Qwen 7B単一モデル常駐化とJSON自己修正ループの実装"）を行ってください。推測による git add . は厳禁です。
