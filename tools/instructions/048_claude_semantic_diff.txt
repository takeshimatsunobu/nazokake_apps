【ミッション: 置換エンジンの論理破壊検知 - Semantic Diffの実装 (Epic 1 防弾化 - 追加課題 G)】
LLMが対象外のトップレベルノード（型ヒント付き代入や無関係な関数など）を誤って削除してしまう「論理破壊」を防ぐため、tools/ast_modifier.py にセマンティック差分検証を導入してください。

Step 1: トップレベル構造の抽出機構の実装
tools/ast_modifier.py 内に、astモジュールを用いてトップレベルの識別子を抽出するヘルパー関数 def _get_top_level_names(code_str: str) -> set[str]: を実装してください。
・ast.parse(code_str) で構文木を生成し、tree.body を走査する。
・ast.FunctionDef, ast.AsyncFunctionDef, ast.ClassDef, ast.Assign, ast.AnnAssign などの主要なトップレベルノードから名前（識別子）を抽出し、セットとして返す。
※AnnAssign の場合は node.target.id、Assign の場合は node.targets の各要素の id など、ノードの型に応じた安全な抽出を行うこと。

Step 2: apply_modification への検証ロジック組み込み
apply_modification の処理内において、置換前（元のコード）と置換後（生成されたコード）のそれぞれで _get_top_level_names を実行してください。
・元のコードの識別子セットから、target_name（今回置換対象のノード）を除外した「保護すべき識別子セット」を定義する。
・置換後のコードの識別子セットが、この「保護すべき識別子セット」を完全に包含しているか検証する。
・欠落が検知された場合、または予期せぬトップレベルノードが追加された場合は、即座に ValueError または Pydantic の ValidationError ("セマンティック差分検証エラー: 予期せぬノードの消失または追加を検知しました") を送出し、ファイル保存処理（アトミック書き込み）を決定論的にブロックする。

Step 3: スモークテストとクリーンアップ

隔離環境に _tmp_semantic_test.py を作成し、ダミーの関数 foo() と、型ヒント付きグローバル変数 GLOBAL_VAR: int = 100 を定義してください。

foo() を置換する指示JSON（ _tmp_semantic_instr.json ）を作成し、その際 LLM のミスを模して new_code から GLOBAL_VAR を意図的に欠落させたダーティデータを渡してください。

実行結果として、セマンティック差分検証エラーが確実に発生・送出され、_tmp_semantic_test.py が上書きされずに無傷で保護されることを確認してください。

修正後の tools/ast_modifier.py に対して uv run ruff check --fix tools/ast_modifier.py を実行し、Linterを通過させてください。

テスト完了後、作成した一時テストファイル群を削除し、実行結果を報告してください。
