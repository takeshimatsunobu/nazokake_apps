【ミッション: プロビジョニングスクリプトのレジリエンス強化（手動リトライの排除）】
SREの観点から、現在の run_verification_server.ps1 の設計は Reject（差し戻し） します。GCPのOS LoginやIAPプロビジョニングのタイムラグによってスクリプトがクラッシュし、人間に手動での再実行を求める設計は「ワンタッチ・プロビジョニング」の要件を満たしていません。一時的なインフラの遅延をフェイルファストの成功と言い訳にすることは許されません。
以下の要件（Must Fix）に基づき、スクリプトを改修してください。

自律的リトライの実装（Exponential Backoff）
Step 3（gcloud compute scp）および Step 4（gcloud compute ssh）のコマンド実行において、タイムラグによる一時的な認証エラー（Exit Code 1等）が発生した場合、即座にスクリプトを異常終了させないこと。最大試行回数（例: 5回）を設け、失敗時には数秒待機してから自動的にリトライするループ処理を実装してください。

真のワンタッチ自動化の証明
人間の手動リトライに依存せず、スクリプト単体で「インフラの状態変化の待ち時間」を吸収し、確実に後続のコンテナ起動まで完走する堅牢性（レジリエンス）を持たせる構造へリファクタリングすること。

実装後、PowerShellの構文エラーがないことを確認し、変更した tools/deploy/run_verification_server.ps1 をコミットしてください。※絶対制約: git add . は厳禁です。
