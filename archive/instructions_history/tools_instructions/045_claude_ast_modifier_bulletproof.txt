【ミッション: 置換エンジンの堅牢化 - 多段バリデーションの実装 (Epic 1 拡張)】

LLMによるハルシネーションからコードベースを保護するため、`tools/ast_modifier.py` に `ast.parse` を用いた構文的妥当性のバリデーションゲートを追加してください。

### Step 1: バリデーションゲートの実装
1. `tools/ast_modifier.py` を開き、LibCSTによって置換された新しいコード文字列（`modified_code` 等）を取得している箇所を特定してください。
2. ファイルへの書き込み（`target_path.write_text(...)`）を実行する**直前**に、以下の処理を追加してください。
   - `import ast` を用いて、`ast.parse(modified_code)` を実行する。
   - `SyntaxError` が発生した場合はキャッチし、「[Fatal] 置換後のコードに構文エラーが存在するため、書き込みを中止します」という旨のエラーログを出力し、`sys.exit(1)` で直ちに処理を中断する。

### Step 2: ネガティブテスト（破壊防御）の実行
1. 隔離環境にダミーのPythonファイル `_tmp_ast_test.py` を作成してください。
2. その中の関数を、**意図的に構文エラーを含むコード（例: 閉じ括弧が足りない等）** に置換しようとするタスクJSONを作成してください。
3. `uv run python tools/ast_modifier.py` にそのJSONを渡し、スクリプトが `SyntaxError` を検知して `Exit Code 1` で異常終了し、実ファイルが**一切変更されていないこと**を確認してください。

### Step 3: 報告とクリーンアップ
1. 修正後の `tools/ast_modifier.py` に対して `uv run ruff check --fix tools/ast_modifier.py` を実行してください。
2. ネガティブテストの実行結果（エラーログの出力とファイルの保護状態）を報告し、一時ファイルは削除してください。
