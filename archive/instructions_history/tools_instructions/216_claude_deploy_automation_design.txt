【ミッション: デプロイ自動化・防弾化のアーキテクチャ設計（CI/CDとコンテナ化）】

ASTを用いた決定論的なファクト抽出と、エンコーディングエラーの自律修復、素晴らしい仕事です。
しかし、プロジェクトの優先順位を緊急変更します。中高生向けのドキュメント作成（概念設計フェーズ）は後回しとし、「なぞかけアプリの安全で再現性のあるデプロイの完全貫通」を最優先（P0）タスクとします。
先ほど抽出した docs/architecture_facts.json をシステムの真のコンテキスト（SSoT）として保持したまま、以下の要件に従ってデプロイ自動化の実装フェーズ（まずは設計）へ移行してください。

Step 1: インフラの手動依存からの脱却
現在の「人間がSSHして初期化する」または「ローカルから手動スクリプトを叩く」という脆い状態（ScriptOps）から脱却するため、CI/CDパイプライン（例: Cloud Build）の構築とコンテナ化（Cloud Runへのデプロイ）に向けた設計を開始してください。

Step 2: SSoTの活用と決定論的パイプライン
architecture_facts.json から読み取れるバックエンド（FastAPI等）や依存関係を正確に反映し、ビルドやデプロイ時に環境依存エラーが起きない決定論的なパイプライン設計を提案してください。

Step 3: 設計案の提示と待機（※まだコード変更・実装は行わないこと）
どのようなアーキテクチャ（例: Cloud Build + Artifact Registry + Cloud Run / Jobs）でデプロイを自動化・防弾化すべきか、プロのSREとしての設計案をテキストで出力し、ユーザーのApprove（承認）を待機してください。
