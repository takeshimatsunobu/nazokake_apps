【ミッション: LLM出力の防衛的正規化 - 堅牢なコード抽出機構の実装 (Epic 1 防弾化 - 課題B)】

LLMが `new_code` の前後に自然言語の解説（ノード外の解説テキスト）やおしゃべりを混入させたり、マークダウンのコードブロックを付与したりした場合に、ASTパーサーが SyntaxError を起こして処理が停止するトイルを防ぐため、堅牢なコード抽出機構を実装してください。

### Step 1: 正規表現によるコード抽出ロジックの実装
1. `tools/ast_modifier.py` 内に、文字列からPythonコードのみを安全に抽出するヘルパー関数 `def _extract_python_code(text: str) -> str:` を定義してください。
   - 単純な両端トリムや置換ではなく、正規表現（非貪欲マッチかつ複数行モード）を使用すること。
   - テキスト全体から最初に見つかったマークダウンのコードブロック（バッククォート3つとpython指定で囲まれた純粋なコード部分）を抽出するロジックとすること。
   - 【最重要】LLMがコードブロックの装飾を付けずにコードのみを出力した場合を考慮し、正規表現でマッチしない場合は、元のテキスト（前後の空白をトリムしたもの）をそのままPythonコードとして返却するフォールバック機構を必ず組み込むこと。
2. ファイル書き込みロジックの最上流（JSONから `new_code` を抽出した直後、かつASTでパースする前）にこの関数を適用し、ダーティな入力データを強制的に正規化してください。

### Step 2: 意地悪な出力（ノイズ混入）に対するデータ耐性テスト
1. `_tmp_extractor_test.py` を作成し、ダミー関数 `def foo(): return 1` を定義してください。
2. テスト用の指示書 `_tmp_instr.json` を作成し、`new_code` に意図的に前後の解説ノイズとマークダウン装飾を含めた文字列を記述してください。
3. `uv run python tools/ast_modifier.py _tmp_instr.json` を実行し、前後の日本語テキストによって SyntaxError でクラッシュすることなく安全にコードが抽出・置換され、ファイルの中身が純粋な `return 999` の関数に更新されることを確認してください。
4. 続いて、マークダウン装飾が一切ない純粋なコード文字列だけの指示書も正常に通過すること（フォールバックの検証）を確認してください。

### Step 3: 報告とクリーンアップ
1. 実装前後で `uv run ruff check --fix tools/ast_modifier.py` を実行し、静的解析エラーがないことを確認してください。
2. ダーティデータ耐性テスト（ノイズあり/ノイズなしフォールバック）の実行結果を報告し、テスト用の一時ファイル群を削除してください。
