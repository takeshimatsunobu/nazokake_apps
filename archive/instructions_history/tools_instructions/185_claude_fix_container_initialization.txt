【SREアーキテクト監査：コンテナ初期化シーケンスの自動化とFail-Closed原則の徹底】
現在のコンテナインフラおよびデーモン設計について、SREの観点から明確に差し戻し（Reject）を通達します。
Git不在によるクリーンアップ失敗の握り潰し（Fail-Open）や、人間による手動マイグレーションを前提とした設計は、システムの自律運用要件に違反します。以下の是正要件（Must Fix）に基づき、アーキテクチャを修正してください。

DockerfileへのGit注入と構成ドリフトの解消
infra/verification_env/mlops_scheduler.Dockerfile の依存関係インストール層に apt-get install -y git（または適切なパッケージマネージャのコマンド）を追加し、コンテナイメージ内に決定論的にGitを導入してください。

起動初期化シーケンス（自動マイグレーション）の組み込み
手動でのスキーマ更新を永久に廃止します。tools/scheduler_daemon.py を改修し、デーモンの稼働ループに入る前の初期化ステップとして tools/run_migrations.py を同期的に実行するロジックを実装してください。マイグレーションが失敗した場合は即座にプロセスを終了（Exit 1）させてください。

クリーンアップ機構の厳格なFail-Closed化
Gitコマンドの不在や、クリーンアップ処理の失敗をサイレントに握り潰す例外処理を撤去してください。ストレージ枯渇を防ぐ必須プロセスであるため、エラー発生時はログを出力した上で即座に Exit 1 を返し、不完全な状態でのシステム稼働を物理的に遮断してください。

実装後、静的解析を実行し、変更したファイル群を明示的に指定してGitコミットを行ってください。
※絶対制約: git add . は厳禁です。必ず対象ファイルパスを個別に指定すること。
