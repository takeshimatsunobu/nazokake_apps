【ミッション: コストゼロのローカルモックを用いたN=100規模ストレステスト (Epic 2 拡張 - 追加課題 M)】
防弾化されたローカルツール群（Ruff, Pyright, LibCST AST置換）のスケーラビリティを証明するため、Claude APIを一切叩かない（APIコストゼロの）純粋なローカル・ストレステストを構築・実行してください。

Step 1: ダミーファイルとタスクの自動生成スクリプト作成
隔離環境に _tmp_stress_generator.py を作成し、以下の要件でテストデータを生成させてください。
・_tmp_stress_targets/ フォルダを作成する。
・行数の異なるダミーPythonファイル（50行、500行、2000行、5000行）を各25個（計100個）自動生成する。ファイル内には無駄なコメントやクラスを大量に詰め込み行数を稼ぐこと。
・各ファイルの中に、置換対象となるダミー関数 def target_func_X(): pass を1つずつ仕込む。
・これら100個のファイルを対象とした、Phase 2出力相当のタスクJSON配列（mode: ast_replace, target_name, new_code を含む）を生成し、_tmp_stress_tasks.json として保存する。

Step 2: オフライン・パイプラインの連続実行スクリプト作成
_tmp_stress_runner.py を作成し、以下の要件でテストを実行・計測させてください。
・Step 1で生成した _tmp_stress_tasks.json を読み込む。
・Claude API（phase2）は絶対に呼び出さないこと。
・Nazo-Agentのローカル検証ロジック（phase0_ruff_autofix 相当のLinter実行、Pyrightによる型チェック、および phase3_aider_execution への mode: ast_replace による直接タスク投入）のみを直列で100回連続実行する。
・ファイル規模（50行〜5000行）ごとに、ASTパースおよび置換処理にかかった時間（レイテンシ）を計測・集計する。

Step 3: スモークテスト（ストレステスト）の実行とクリーンアップ

uv run python _tmp_stress_generator.py を実行し、100件のテストデータを生成してください。

uv run python _tmp_stress_runner.py を実行し、ストレステストを完走させてください（API通信が発生していないことを確認すること）。

実行完了後、ファイル行数と処理時間（レイテンシ）の関係性を示すサマリー表を出力してください。線形（O(N)）でスケールしているか、指数関数的な劣化がないかを評価してください。

テスト完了後、作成した一時スクリプト群、JSON、および _tmp_stress_targets/ ディレクトリをすべて完全に削除（クリーンアップ）し、実行結果を報告してください。
